# Назва проєкту: Агентство нерухомості

**Короткий опис:** модель агентства нерухомості. Клієнти обирають житло за допомогою рієлторів, які, в свою чергу, проводять угоди.

**Опис предметної області:** система вирішує проблему підбору нерухомості. Користувачами системи є люди, які хочуть легко купити/продати житло та рієлтори, у яких буде платформа для заробітку.

**Перелік учасників:** Олексій Гунько, Кирило Колісниченко, Ян Бойко (всі ІПЗ-24-1).

**Основні сценарії використання:**
1. Клієнт обирає об'єкт нерухомості на сайті.
2. Рієлтор розміщує новий об'єкт.
3. Рієлтор проводить угоду.
4. Рієлтор знімає об'єкт із сайту.

**Перелік ресурсів API:**
1. Список об'єктів нерухомості (Properties).
2. Список клієнтів (Clients).
3. Список рієлторів (Agents).
4. Список угод (Deals).

**Перелік реалізованих endpoints:**
* Отримання об'єктів, угод, клієнтів та рієлторів за ID (GET).
* Отримання списків із підтримкою фільтрації (за ціною, кімнатами, статусом тощо) та сортування (GET).
* Зміна характеристик сутностей (PUT).
* Створення нових записів у системі (POST).
* Видалення записів (DELETE).

## База даних та структура моделі

**Використана СУБД:**
У проєкті використовується **SQLite** як легка реляційна база даних для розробки. Взаємодія з БД реалізована через ORM-фреймворк **Entity Framework Core 10.0** за підходом *Code-First* (схема БД генерується на основі коду C#).

**Основні сутності:**
* `Property` (Нерухомість) — зберігає інформацію про об'єкт: адресу, ціну, тип приміщення, кількість кімнат та статус доступності.
* `Client` (Клієнт) — контактні дані клієнта: ПІБ, Email, номер телефону.
* `Agent` (Рієлтор) — робочі дані співробітника: ПІБ, Email, телефон, номер ліцензії, статус активності.
* `Deal` (Угода) — факт укладання договору. Містить дату, кінцеву ціну та поточний статус (наприклад, Pending).

**Зв'язки між сутностями:**
Сутність `Deal` (Угода) виступає центральною таблицею, яка об'єднує інші сутності через відношення **Один-до-багатьох (1:N)**:
* **1** об'єкт `Property` може мати багато угод (наприклад, історія оренди), але **1** конкретна угода стосується лише **1** об'єкта нерухомості (зв'язок через `PropertyId`).
* **1** `Client` може укладати багато угод, але **1** угода належить **1** клієнту (зв'язок через `ClientId`).
* **1** `Agent` (Рієлтор) може проводити багато угод, але за **1** конкретну угоду відповідає **1** рієлтор (зв'язок через `RealtorId`).
Усі зв'язки налаштовані за допомогою зовнішніх ключів (`ForeignKey`) із підтримкою каскадного видалення.

## Інструкція із запуску та налаштування бази даних

**Налаштування підключення:**
Рядок підключення до бази даних зберігається у файлі `appsettings.json`:
```json
"ConnectionStrings": {
  "DefaultConnection": "Data Source=realestate.db"
}
Файл фізичної бази даних (realestate.db) генерується автоматично у кореневій папці проєкту під час першого застосування міграцій.

**Порядок застосування міграцій:**
Для ініціалізації бази даних на новому комп'ютері або після оновлення моделей необхідно застосувати міграції EF Core.
Відкрийте термінал у кореневій папці проєкту та виконайте наступні кроки:

Для створення/оновлення бази даних до актуального стану (накатування наявних міграцій):
dotnet ef database update
(Опціонально) Якщо ви внесли зміни в класи моделей (наприклад, додали нове поле) і хочете зафіксувати їх:
dotnet ef migrations add <НазваВашоїМіграції>
Після успішного створення міграції знову виконайте dotnet ef database update.

Запуск проєкту:

Запустіть проєкт у Visual Studio за допомогою F5 або виконайте команду dotnet run у терміналі.

Введіть в адресному рядку браузера http://localhost:[порт]/swagger (порт можна знайти у файлі Properties/launchSettings.json або у виводі терміналу).

Через інтерфейс Swagger UI ви можете ознайомитися з документацією API та протестувати всі реалізовані REST-операції.
